Stripe Account Setup

TimeVault — Client Onboarding

TimeVault takes card payments, holds each payment for a period the user chooses, then pays the money out to that user's own bank account. That payout leg means a standard Stripe account is not enough — the account must also be approved for Stripe Connect with Custom accounts. That approval is the only step with a waiting period, so it should be started first.

Steps 1–3 — Account, Connect, keys

1. Create and verify the account

Sign up at dashboard.stripe.com/register with a company email more than one person can reach — Stripe sends password resets and risk notices there. Turn on two-factor authentication, then complete Activate your account: business type and registration number, address, directors, and the business bank account Stripe pays TimeVault's own revenue into. Upload ID when asked; verification usually clears in one to two business days.

2. Apply for Connect with Custom accounts

Open Connect in the sidebar → Get started → Platform or marketplace → account type Custom. Standard and Express will not work: the app creates accounts through the API and collects bank details in its own screens. Complete the platform profile — who your users are, what they are paid for, average payout size and expected monthly volume — then submit and wait for approval by email.

3. Collect the API keys

Go to Developers → API keys. The Test mode toggle at the top right changes which keys are shown.

KeyLooks likeUsed bySecret?

Send keys through a password manager or encrypted channel — never email or chat. The live secret key can move money out of the business's account. If one is ever exposed, click Roll key in the dashboard immediately.

Step 4 — Create the webhook endpoint

A webhook is how Stripe tells TimeVault a payment actually succeeded. Without it a user could be charged and the app would never record it — this step is not optional. Go to Developers → Webhooks → Add endpoint and set the URL to: 

https://api.timevaultapp.co/api/stripe/webhook

Under Select events, add exactly these three:

EventWhat it means
payment_intent.succeededThe card was charged; start the hold period
payment_intent.payment_failedThe charge was declined; tell the user
payment_intent.canceledThe payment was abandoned or cancelled

Save, open the endpoint, reveal the Signing secret — it begins whsec_ — and copy it. Treat it like the secret key.

Test and live mode have separate endpoints and separate signing secrets. This endpoint is created twice — once in test mode, once at go-live. Using the test secret against live traffic makes every webhook fail verification, and payments silently stop being recorded.

Step 6 — Go live

Only after Connect approval and a successful test payment. Switch out of Test mode, collect the live keys, create the webhook endpoint again in live mode with the same URL and events, and send all three live values across. Then take one real payment for the smallest amount the app allows, confirm the webhook returned 200, and refund it.

To confirm before we finalise: the country the business is registered in, the currencies to accept at launch (the app supports USD, EUR and GBP), and whether the live domain is timevaultapp.co.
